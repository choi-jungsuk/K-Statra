# Antigravity 작업지시문: KOAA SHOW PoC 종료 간담회 자료 논리 흐름 재배치

## 1. 작업 대상

아래 HTML 발표자료를 수정한다.

```text
D:/demostatra-project/KOAA_SHOW_PoC_Report/ain_global_ax_data_briefing/index.html
```

이번 작업은 개별 슬라이드 내용의 세부 수정이 아니라, **전체 발표 흐름을 자연스럽게 재배치**하는 것이다.

현재 자료는 중요한 내용은 잘 들어가 있으나, 새로 추가된 슬라이드들이 앞쪽에 배치되면서 논리 전개가 다소 급하게 느껴진다. 특히 “결론 → 구축 방식 → 비용 산정”이 먼저 나오고, 그 뒤에 “AX 데이터가 무엇인지 / 왜 필요한지 / 어떻게 매칭에 쓰이는지”가 나와 청중이 따라가기 어려울 수 있다.

---

## 2. 재배치의 핵심 원칙

발표 흐름은 아래 순서가 되도록 정리한다.

```text
1. 왜 이 논의가 필요한가?
2. 현재 DB의 한계는 무엇인가?
3. 그래서 AX DB가 무엇이고 왜 필요한가?
4. AX DB는 어떤 구조로 만들 것인가?
5. 실제 구축은 얼마나 현실적으로 할 수 있는가?
6. 보안 우려는 어떻게 해결할 것인가?
7. 구축된 AX DB는 B2B 매칭에 어떻게 쓰이는가?
8. DemoStatra의 차별화 가설은 무엇인가?
9. 연장 PoC에서 무엇을 검증할 것인가?
10. 아인글로벌/KOAA SHOW에는 어떤 효과가 있는가?
11. 이후 정부사업/확장 가능성은 무엇인가?
```

즉, **문제 제기 → AX DB 개념 → 구축 방법 → 비용 산정 → 보안 운영 → 매칭 활용 → 차별화 가설 → 연장 실행계획 → 기대효과** 순서가 되도록 한다.

## 3. 현재 슬라이드 목록

현재 HTML 기준 슬라이드는 다음과 같이 구성되어 있다.

```text
01. Cover: KOAA SHOW PoC 종료 간담회
02. PoC 핵심 결론: AX DB 구축과 보안 운영 구조가 먼저입니다
03. AX DB 구축 방식: 자동 수집 + AI 분류 + 담당자 검수
04. AX DB 구축비용은 파일럿 실측 후 단계별로 산정합니다
05. AI 시대 고객 정보 관리 고도화 방향
06. AX 프로필 데이터 (양식)
07. AX B2B 매칭 서비스의 원리
08. AX 프로필은 AI가 읽을 수 있는 기업 소개서입니다
09. (재)아인글로벌 자체 DB 중심의 보안 운영 구조
10. AX 데이터 구축 절차
11. 실거래 기반 군집 추천 가설과 3개월 검증 로드맵
12. 향후 검토 가능 정부 사업
13. KOAA SHOW 운영 관점의 기대 효과
```

현재 문제점:

1. 2페이지에서 최종 결론이 너무 먼저 나온다.
2. 3~4페이지에 구축 방식과 비용 산정이 나오는데, 청중은 아직 AX 프로필이 무엇인지 충분히 이해하지 못한 상태다.
3. 보안 운영 구조가 뒤쪽에 있어, 아인글로벌의 가장 큰 우려인 데이터 보안 논리가 중간에 늦게 등장한다.
4. 기대효과가 정부사업보다 뒤에 있어, 발표 마무리의 임팩트가 약해질 수 있다.
5. 실거래 기반 군집 추천 가설과 3개월 검증 로드맵이 한 장에 섞여 있어 좋지만, 그 전에 매칭 원리와 AX DB 구축 방식이 충분히 설명된 뒤 나와야 한다.

### Slide 02: 문제 제기 + 핵심 결론 브릿지

기존 2페이지를 유지하되 제목과 톤을 약간 조정한다.

현재 제목:

```text
PoC 핵심 결론: AX DB 구축과 보안 운영 구조가 먼저입니다
```

추천 제목:

```text
PoC를 통해 확인한 핵심 과제: AX DB와 보안 운영 구조
```

또는:

```text
현재 DB를 AI 매칭용 AX DB로 전환하는 것이 첫 과제입니다
```

슬라이드 역할:

- 발표 전체의 결론을 너무 세게 단정하기보다, “이번 PoC에서 확인한 핵심 과제”로 제시한다.
- 3개 핵심 카드는 유지한다.
  1. AX DB 구축이 우선
  2. 원천 DB는 기관이 직접 통제
  3. 2~3개월 연장 검증

상단 요약 문구는 너무 길면 줄인다.

추천 요약:

```text
이번 PoC는 단순 알고리즘 문제가 아니라, AI가 이해할 수 있는 AX 데이터 구조와 기관 주도형 보안 DB 운영 체계가 먼저 필요하다는 점을 확인하는 과정이었습니다.
```

하단에는 아래 브릿지 문장을 넣는다.

```text
이후 페이지에서는 AX DB가 무엇인지, 어떻게 구축·검수하고, 어떤 보안 구조에서 운영할 수 있는지 순서대로 설명합니다.
```

### Slide 07: 파일럿 기반 비용 산정

기존 4페이지를 7페이지로 이동한다.

제목 유지:

```text

```

이유:

- 구축 방법을 설명한 직후, “그럼 시간과 비용은 어떻게 산정할 것인가?”라는 질문에 답한다.

중요:

- 구체 비용을 현재 단정하지 않는다.
- 국내업체 1,000개사 + 해외 바이어 1,000개사 파일럿을 먼저 수행한다는 메시지를 분명히 한다.
- 2,000개사 → 1만 → 3만 → 6만 → 10만 확장 구조를 유지한다.

권장 표현:

```text
접속 승인, 권한 관리, 작업 로그, 데이터 반출 기록을 통해 보안 위험을 최소화하고 감사 추적성을 확보합니다.
```

## 10. 금지 표현 유지

재배치 과정에서 아래 표현은 절대 넣지 않는다.

```text
데이터를 안 줘서 못했다
현재 DB로는 AI 매칭이 안 된다
아인글로벌 DB가 부족하다
보안 문제가 없다
유출 우려 원천 해소
예산소진시까지
정확도 검증 완료
거래성사율 향상 입증
전체 구축비용 확정
1천만 원 이하로 전체 구축 가능
```

대신 아래 표현을 사용한다.

```text
현 DB는 AI 매칭에 필요한 AX 프로필 구조로 표준화·보강할 필요가 있다
원천 데이터 직접 이전은 보안 우려로 보류하고 기관 주도형 DB 운영 구조를 제안한다
보안 위험을 최소화하고 감사 추적성을 확보한다
기배정 연산·운영 예산 범위 내에서 단계적으로 검증한다
담당자 피드백 기반 추천 품질 평가
파일럿 실측 기반 단계별 비용 산정
```

## 11. 최종 검수 기준

작업 후 아래 기준으로 검수한다.

1. 슬라이드 순서가 문제 제기 → AX 개념 → 구축 방식 → 비용 산정 → 보안 → 매칭 원리 → 차별화 가설 → 기대효과 → 후속사업 순서인가?
2. 2페이지에서 너무 많은 결론을 한꺼번에 던지지 않는가?
3. AX 프로필 개념을 설명한 뒤 AX 프로필 양식이 나오는가?
4. 구축 방식 설명 후 파일럿 기반 비용 산정이 나오는가?
5. 보안 운영 구조가 너무 뒤로 밀리지 않고 중간에 설득력 있게 배치되었는가?
6. 매칭 원리와 실거래 기반 군집 추천 가설이 자연스럽게 이어지는가?
7. 기대효과가 정부사업보다 먼저 나와 아인글로벌 입장에서 직접 효익이 먼저 보이는가?
8. 페이지 번호와 HTML 주석이 정확히 맞는가?
9. 중복 문구와 과장 표현이 제거되었는가?
