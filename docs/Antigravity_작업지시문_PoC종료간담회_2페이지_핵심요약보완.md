## 2. 페이지의 목적

2페이지는 아래 3가지를 한눈에 보여줘야 한다.

1. 현재 보유 DB를 그대로 AI 매칭에 쓰기에는 AX 데이터 구조가 부족하므로, AX DB 구축이 우선 필요하다.
2. 원천 DB는 (재)아인글로벌이 직접 통제하고, 개발자는 승인된 범위에서만 접속·작업하는 보안 운영 구조가 필요하다.
3. 당초 계획된 기배정 연산·운영 예산 범위 내에서 약 2~3개월 PoC를 연장하여 AX DB 구축과 B2B 매칭 성능 개선을 단계적으로 검증한다.

단, 표현은 방어적으로 작성한다.

피해야 할 표현:

```text
현재 DB로는 AI 매칭이 안 된다
아인글로벌 DB가 부족하다
데이터를 안 줘서 못했다
보안 문제가 없다
예산소진시까지
최종 성능 검증
정확도 검증 완료
```

권장 표현:

```text
현 DB는 AI 매칭에 필요한 표준화된 AX 프로필 구조로 전환할 필요가 있다
원천 데이터 직접 이전은 보안 우려로 보류하고, 기관 주도형 보안 DB 운영 구조를 제안한다
접속 승인, 권한 관리, 접속 기록, 데이터 복사 기록을 남겨 데이터 반출 위험을 최소화한다
기배정 연산·운영 예산 범위 내에서 약 2~3개월간 단계적 검증을 진행한다
담당자 피드백 기반 추천 품질 평가와 운영 가능성 검증을 진행한다
```

## 5. 2페이지 본문 구성: 3개 핵심 카드

페이지 중앙에는 3개의 카드 또는 3단 구조를 사용한다.

### 카드 1. AX DB 구축이 우선

제목:

```text
1. AX DB 구축이 우선
```

본문:

```text
현재 보유 DB는 기업 기본정보 중심이므로, AI 기반 B2B 매칭에 필요한 품목·인증·수요·타겟국가·거래조건·바이어 유형 등의 필드를 표준화한 AX 프로필 구조로 전환할 필요가 있습니다.
```

강조 문구:

```text
AI 매칭의 출발점은 알고리즘보다 데이터 구조입니다.
```

---

### 카드 2. 기관 주도형 보안 DB 운영

제목:

```text
2. 원천 DB는 기관이 직접 통제
```

본문:

```text
보안상 원천 DB를 외부로 이전하지 않고, (재)아인글로벌이 직접 MongoDB Atlas 등 클라우드 DB 계정을 개설·관리합니다. 담당자가 비밀번호·API Key·접속 권한을 통제하고, 개발자는 승인된 계정과 기간에 한해 접속하여 작업합니다.
```

강조 문구:

```text
승인 기반 접속 + 권한 관리 + 작업 로그 + 데이터 반출 기록으로 보안 위험을 최소화합니다.
```

DB 추천 문구:

```text
권장 DB 후보: MongoDB Atlas, PostgreSQL + pgvector, Neo4j Aura
```

단, 슬라이드에는 너무 복잡하게 쓰지 말고 아래처럼 간단히 표시한다.

```text
MongoDB Atlas 중심 검토 / 필요 시 Vector DB·Graph DB 연계
```

## 8. DB 운영 구조 도식 추가 가능

공간이 있으면 카드 2 안에 작은 도식을 넣는다.

```text
(재)아인글로벌
DB 계정 개설·PW/API Key 통제
        ↓ 승인
개발자 / DemoStatra 팀
승인된 계정·기간·권한으로 접속
        ↓ 작업
AX 프로필 구조화 / 매칭 엔진 개선
        ↓ 기록
접속 로그 · 작업 로그 · 데이터 반출 기록 보관
```

이 도식은 보안 우려를 줄이는 데 중요하다.
